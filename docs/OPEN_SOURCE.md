# 开源维护检查

本文件用于维护者准备公开代码和发布新版本。代码使用 [MIT License](../LICENSE)；第三方依赖、上游作品和模型权重仍遵守各自许可证。确认代码与资产的公开权利应由维护者完成，扫描通过不等同于权利审核。

## 仓库基线

公开分发的 GitHub 仓库以整理后的当前代码建立新的初始提交，不保留此前 Git 提交链、实验分支、版本标签或 AI notes。实验分支中独立的 `NativeInput/` 包已纳入源码和测试，但未接入 App。早期开发预发布和对应 GitHub Actions 记录已移除；`CHANGELOG.md` 的旧版本条目只用于说明产品演进。维护者可在访问受限的私有远程保留迁移前的备份分支，此分支不得同步到公开远程。

需要使用此基线的协作者应重新克隆。不要把旧克隆的分支、标签或 notes 推送回来，也不要将旧 Git 目录、bundle 备份或本机安装产物发布为源码附件。历史重置属于一次性治理，日常仍遵循 [AGENTS.md](../AGENTS.md) 的 `master` 开发流程。

## 提交前

1. 检查 staged diff 和文件名，确认没有本机配置、密钥、证书、录音、转写、模型缓存或构建缓存。
2. 使用公开身份提交，检查作者和提交者邮箱；推荐使用 GitHub 设置中的 noreply 地址。
3. 扫描源码和可达历史。例如，在本机安装 Gitleaks 后运行：

   ```bash
   gitleaks dir . --redact
   gitleaks git . --log-opts="--all" --redact
   git log --all --format='%an <%ae> | %cn <%ce>'
   git for-each-ref --format='%(refname)'
   ```

   `dir` 扫描可能包含被 Git 忽略的本机文件；不要直接分享报告。报告应保存在仓库之外。任何真实凭据必须先撤销或轮换，删除 Git 记录不能使已泄露凭据恢复安全。

4. 运行 `npm run check` 及 [发布流程](RELEASING.md) 中的 Python 依赖审计。原生输入实验的测试只验证状态，不代替硬件、权限及操作系统版本测试。
5. 检查截图和音频等非文本资产，以及 README、变更记录和发布附件是否与当前代码一致。

`.gitignore` 是辅助措施，已被跟踪的文件不会因新增忽略规则而自动移除。不要用 `git add -f` 绕过凭据、录音或备份文件的忽略规则。

## 公开仓库前

- 从公开分发远程新克隆，确认仅包含预期分支和新历史，检查远程 notes、标签及其他可见引用。私有远程的恢复分支单独管理，不得通过 mirror 推送到公开仓库。
- 检查托管平台上的 Release、Actions 日志与产物、缓存、Issue/附件和其他公开入口；它们不属于普通 Git 工作树扫描范围。
- 确认 [安全报告入口](../SECURITY.md)、[贡献流程](../CONTRIBUTING.md)、[帮助入口](../SUPPORT.md) 和[行为准则](../CODE_OF_CONDUCT.md) 可用。
- 公开 GitHub 仓库后，在平台设置中启用私密漏洞报告及可用的 secret scanning / push protection。是否公开由仓库所有者决定，代码清理不会自动更改可见性。
- 未经 Developer ID 签名与公证的包必须标为开发预发布，不能宣称为稳定分发包。

## 历史清理的边界

强制更新远程引用并删除分支、标签、notes 或托管记录，可移除常规入口，但不保证托管服务立即清除不可达对象、内部缓存、备份或其他人的克隆。若旧历史含必须彻底移除的数据，请联系各托管平台管理员处理对象保留与缓存。私有恢复备份只能保存在访问受限的位置，不随公开源码分发。
